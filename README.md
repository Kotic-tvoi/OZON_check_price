# Ozon Price Reader — единая сессия Chrome

Сбор цен с витрины Ozon **только на чтение** для Google Таблицы. Код не меняет цены на Ozon и не хранит базу данных/историю цен на сервере. Запрос содержит **один URL ПВЗ и до 100 артикулов**. Один Chrome выбирает ПВЗ один раз и проверяет все товары последовательно, возвращая **один JSON-ответ**. Пакетов по 16 нет.

Исходная версия с обработкой пакетами по 16 SKU сохранена в ветке [`archive/batched-16-working-2026-10-08`](https://github.com/Kotic-tvoi/OZON_check_price/tree/archive/batched-16-working-2026-10-08).

## Локальное тестирование (Git Bash в Windows)

```bash
python -m pip install -r app/requirements.txt
python tests/local_single_session.py --limit 100 --headed
```

Файл `SKU_Ozon.txt` находится в корне проекта и содержит по одному Ozon SKU на строке. Скрипт берёт первые 100 артикулов и запускает `scan_items` **ровно один раз**. Для оставшихся строк файла:

```bash
python tests/local_single_session.py --offset 100 --limit 19 --headed
```

Указанные 119 артикулов в одном запросе не поддерживаются: предусмотрено до 100. Другая ссылка на ПВЗ передаётся через `--pvz https://www.ozon.ru/geo/moskva/442329/`. Скрипт выводит цены, статусы и время **только в терминал**, без файла с результатами.

Парсер использует Selenium, переиспользует Chrome на все товары одного запроса и проверяет выбранный адрес перед принятием цены. Если товар недоступен или переадресован на поиск, возвращает `price: null`, `status: unavailable` — цены из рекомендаций не используются.

**Проверка доступа:** при устойчивой CAPTCHA / ошибке установки ПВЗ текущая попытка завершается. Имеющаяся логика повторов запускает **весь запрос** с новым Chrome (до 5 попыток, без обязательной паузы); частичные результаты прежней попытки отбрасываются. Это может увеличить время при поздней блокировке, но соответствует принципу «всё или ничего». CAPTCHA не решается автоматически. Если блокировка продолжается, возвращаются статусы ошибки, без подстановки цен.

## Сервер и API

Запуск:

```bash
export OZON_API_TOKEN='replace-with-a-long-secret'
python app/server.py
```

Сервис по умолчанию слушает `127.0.0.1:8765`, внешние запросы Google Apps Script требуют HTTPS reverse proxy. Токен передаётся в `Authorization: Bearer ...`.

Пример запроса:

```http
POST /v1/prices
Content-Type: application/json
Authorization: Bearer your-token

{"pvz_url":"https://www.ozon.ru/geo/moskva/442329/","articles":["380181277","1648595002"]}
```

В JSON находятся `results`, `summary`, `pvz_url` и `read_only`. В каждой строке присутствуют артикул, цена (целое число либо `null`), статус, время проверки и диагностические поля. Проверка **типа цены не выполняется**. Excel по-прежнему доступен отдельно через `POST /v1/prices.xlsx`, формируется в памяти.

Дополнительные методы: `POST /v1/pvz/check`, `POST /v1/diagnostics/price`, `GET /health`.

## Google Таблица

Столбец **A** — артикул, **B** — конечная цена, **H2** — одна ссылка на ПВЗ для всего запроса. Код `google_sheets/Code.gs` вставьте в **Расширения → Apps Script**, обновите таблицу и используйте меню **Ozon — цены → Настроить подключение** (HTTPS и API-токен), затем **Обновить все цены**.

Один запуск отправляет **один запрос** со всеми непустыми артикулами (максимум 100). При отсутствии цены пишется **«Нет данных»**, при CAPTCHA или неверном ПВЗ новые значения в таблицу **не записываются**. Если произошёл сбой, старые цены остаются в таблице, поэтому они **не должны трактоваться как результаты нового запуска** — повторите обновление. Постоянной базы цен нет; таблица — единственное место хранения отображаемых результатов.

Google Apps Script ограничен по времени выполнения. При ~100 SKU сбор может занять больше времени, особенно при перезапусках Chrome; при тайм-ауте вернёмся к оценке другого способа организации запросов. Сохранённая пакетная ветка позволяет вернуться к предыдущей схеме.
